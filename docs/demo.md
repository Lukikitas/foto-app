# Demo para presentación

La demo se publica en el enlace habitual: https://delivery.star-app.com.ar/. Para abrirla localmente, ejecutar `npm run demo` desde la raíz y visitar http://127.0.0.1:4174/. Empieza en Métricas, incluso desde un teléfono. No requiere variables ni acceso a Supabase. El APK también queda disponible en `output/demo/Delivery-Star-Camara-DEMO.apk`.

Para generar una copia independiente: `npm run build:demo`. El resultado está en `dist-demo/`. Para revisarlo: `npm run preview:demo`. El workflow de Pages publica esta carpeta por defecto en el dominio habitual. Para restaurar el frontend operativo, ejecutar manualmente el workflow con `web_mode=operational`; conserva su configuración de cierre.

La demo usa las pantallas reales de métricas, desempeño, informe, galería, historial, pendientes y ajustes. Incluye 70 días de datos deterministas, cuatro agregadores y cuatro personas. Cada pedido tiene una fila en la galería; cada queja cuenta exactamente una vez en el historial y en el total diario correspondiente. Los importes recuperados, en disputa y perdidos se calculan con las mismas funciones de la app. Las evidencias son ilustraciones identificadas como ejemplos. Las fechas se ajustan al día de apertura en Argentina.

Recorrido sugerido: Métricas → Resumen (7 días / mes y filtros por agregador), Desempeño e Informe → Galería de pedidos (búsqueda, filtros y evidencia) → Reclamos (lista de ejemplo con tres coincidencias, ya existentes en el historial) → Historial (estados y montos) → Sacar foto (abrir cámara Android o descargarla) → Ajustes.

Es una demostración de lectura: los formularios se pueden explorar, pero los guardados, borrados, subidas y análisis remotos muestran un aviso de modo demo. «Sacar foto» usa un Intent Android con el paquete exacto `app.deliverystar.capture.demo`: abre esa app si está instalada y usa `/demo/camara/` como alternativa de descarga. En escritorio o iPhone lleva directamente a esa página. La resolución de la instalación depende del soporte de Intents del navegador Android; la pantalla también ofrece enlaces explícitos para abrir o descargar. El botón Reiniciar recorrido vuelve al inicio; los datos ficticios no se modifican.

En el modo `demo`, Vite reemplaza el módulo de Supabase por un cliente local sin transporte ni credenciales. Se desactivan la recuperación de la cola de subidas, las tareas automáticas de importación y limpieza, y los avisos de instalación y actualización. El almacenamiento local y de sesión usa claves separadas para conservar los borradores y preferencias operativos sin mostrarlos en la demo. Un service worker mínimo reemplaza al anterior en el dominio: no intercepta navegaciones, no procesa subidas y conserva los datos locales existentes. Una pestaña que todavía muestre el cierre anterior puede requerir recargar después de recibir la actualización. Los comandos normales `npm run dev` y `npm run build` conservan el comportamiento operativo y el cierre temporal.

## Cámara Android

La app nativa tiene su propia variante `demo`, con Cámara habilitada y sin permiso de Internet. Se instala como **Delivery Star · DEMO**, separada del piloto y con archivos propios. Permite mostrar la captura real de ticket y bolsa, lentes, flash, miniaturas y la lista local sin enviar fotos a Supabase. Compilación e instalación en [la guía Android](../android-camera/README.md#apk-de-demostración-sin-base-de-datos).

`npm run prepare:camera-demo` usa el APK local compilado o descarga la versión publicada en Releases cuando no está compilado localmente. Siempre valida tamaño y SHA-256 contra `src/demo/camera-release.json`. Para modificar la cámara, compilar con `.\gradlew.bat :app:assembleDemo` desde `android-camera`, verificar el APK nuevo y actualizar la versión publicada y sus metadatos antes del siguiente despliegue. El servidor demo ofrece la descarga desde ese artefacto verificado y `build:demo` lo incluye en `dist-demo/demo/camara/`. El APK no se copia a `public/` ni se incluye en la compilación operativa.
