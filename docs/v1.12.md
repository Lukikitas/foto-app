# v1.12 — Pendientes por día y recuperación OCR

## Control diario, solo en PC

Pendientes se ofrece en la navegación de escritorio (desde 1024 px). Al reducir la pantalla por debajo de ese límite, se retira la sección y una vista activa de Pendientes vuelve a captura. No se cargan sus documentos mientras no se haya abierto la sección.

El período inicial es el mes en curso, hasta hoy en Argentina. Cada día se despliega por agregador y muestra tres controles:

- Datos guardados: si existe una fila del día/agregador, la carga está realizada. Incluye valores cero, cargas antiguas y parciales; no exige confirmar ni modificar datos existentes. Solo la ausencia de la fila genera una carga pendiente.
- Quejas sin refutar: estado queja, incluyendo vencidas para revisión. Se conserva el plazo existente por plataforma y cero significa sin límite. El acceso al caso permite usar las acciones existentes; las vencidas no ofrecen refutación.
- Refutados en análisis: estado refutado. Se agrupan por fecha del pedido, no por una fecha de envío inventada.

Las diferencias entre totales diarios y casos del historial se explican dentro del detalle como información, sin transformar una carga guardada en pendiente. Los estados aceptado, rechazado y no refutable no cuentan como trabajo abierto.

Se enumeran los días desde la primera actividad registrada. No se crean faltantes anteriores a esa fecha. Los días se ordenan de antiguos a recientes. El día actual se distingue como en curso. Los pendientes fuera del período tienen un aviso y un acceso a todo el historial. Los casos sin fecha válida o sin agregador se conservan visibles para poder corregirlos.

Los botones abren Cargar un día con su fecha y plataforma destacada, o el Historial filtrado al caso. Volver a pendientes conserva filtros, días desplegados y posición. Se vuelve a consultar al regresar, recuperar la conexión, mostrar la pestaña y cada 30 segundos mientras la sección esté abierta. Un error impide mostrar una confirmación de trabajo terminado; no se usa una caché silenciosa para los contadores.

No hay un registro paralelo de tareas ni marcas manuales de día terminado. Todo se deriva de los documentos vigentes de historial y métricas, sin modificar importes, estados o fechas por consultar.

## Recuperación OCR

La normalización de agregadores acepta null/undefined sin ejecutar toUpperCase sobre ellos. La recuperación programada trata un resultado reciente guardado sin código como no_code, con agregador nulo y sin confirmación automática. Una corrección manual continúa teniendo prioridad. Ajustes distingue Terminada con errores cuando una ejecución complete tiene fallos registrados.

La corrección del servidor necesita desplegar order-code-recovery con verificación JWT activa. No requiere migraciones, cambios de secretos ni modificaciones de configuración o de los pedidos existentes.

## Validación

Pruebas: npm test, npm run test:database, npm run lint y npm run build.

La página local /tests/ui/pending.html usa datos ficticios para verificar faltantes, cargas guardadas antiguas/cero, estados, vencimientos, rangos, acceso a carga, resolución simulada y falla de conexión. No guarda datos de producción y no se incluye en el build público. Las pruebas de la Edge Function ejecutan su rama real de resultados guardados con null y códigos válidos, preservando las correcciones manuales.

La prueba visual integrada se realizó con lecturas reales y sin guardar cambios: acceso al día correcto, caso correcto, regreso al día desplegado y menú sin Pendientes a 390 px. A 1024 px no hay desbordamiento horizontal. Se inspeccionaron ambos temas en la prueba aislada.

Resultado: 367 pruebas aprobadas, base aislada aprobada, lint y build aprobados. Se conservan las advertencias de empaquetado existentes sobre tamaño de bundle e import.meta en el service worker.
